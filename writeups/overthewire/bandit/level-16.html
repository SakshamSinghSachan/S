OverTheWire Bandit — Level 16 to Level 17

Introduction

Is writeup ka heading Level 16 → Level 17 hai.

Is level mein current password ko localhost ke port range 31000 se 32000 ke beech kisi service par submit karna hai.

Challenge ke steps:

  1. Port range scan karna.
  2. Open ports identify karna.
  3. SSL/TLS services aur normal services ko separate karna.
  4. Correct SSL service se connect karna.
  5. Current password submit karna.
  6. Service se RSA private key receive karna.
  7. Private key ko file mein save karna.
  8. File permissions chmod 600 se secure karna.
  9. Private key ke through bandit17 user par SSH login karna.
  10. /etc/bandit_pass/bandit17 se password read karna.

31790

Nmap

Nmap Kya Hota Hai?

Nmap ka full form Network Mapper hai. Ye network discovery aur security auditing ke liye use hone wala tool hai.

Nmap ki madad se hum:

  • Open ports find kar sakte hain.
  • Closed ports identify kar sakte hain.
  • Running services detect kar sakte hain.
  • Service versions identify kar sakte hain.
  • Localhost ya authorized network scan kar sakte hain.

Is level mein hum sirf localhost ko scan kar rahe hain, jo authorized Bandit environment hai.

Basic Nmap Command

nmap localhost

Ye common ports scan karta hai.

Specific range scan karne ke liye:

nmap -p 31000-32000 localhost

-p Option

-p 31000-32000

Nmap ko batata hai ki sirf port range 31000 se 32000 tak scan karni hai.

-sV Option

-sV

Service version detection enable karta hai.

Isse Nmap try karta hai identify karne ki:

  • Port par kaunsi service run ho rahi hai.
  • Service SSL/TLS use karti hai ya nahi.
  • Service ka version kya ho sakta hai.

-sC Option

-sC

Nmap ke default scripts run karta hai. Ye additional service information collect karne mein help kar sakta hai.

Complete Scan Command

nmap -sC -sV -p 31000-32000 localhost

Aapke provided command mein -sC, -sV aur port range use hui hai.

Nmap Output Samajhna

Example output:

PORT      STATE SERVICE  VERSION
31046/tcp open  echo
31518/tcp open  ssl/echo
31691/tcp open  echo
31790/tcp open  ssl/unknown
31960/tcp open  echo

PORT

31790/tcp

Meaning:

31790 → Port number
tcp   → Transport protocol

STATE

open

open ka matlab hai ki port par koi service connections accept kar rahi hai.

Other common states:

closed  → Port reachable hai, lekin service listening nahi kar rahi
filtered → Firewall ya filtering ki wajah se status clear nahi hai

SERVICE

echo
ssl/echo
ssl/unknown

Service column Nmap ka best identification guess show karta hai.

Echo Service Aur SSL Service

Echo Service

Echo service client se jo data receive karti hai, wahi data wapas send kar deti hai.

Example:

Client: hello
Server: hello

Challenge mein echo services current password ko next credentials mein convert nahi karti. Woh sirf input wapas echo karti hain.

SSL/Echo Service

ssl/echo

Is service mein SSL/TLS layer ho sakti hai, lekin underlying behavior echo ho sakta hai. Ye correct service nahi hai agar woh sirf input repeat kare.

SSL/Unknown Service

ssl/unknown

Iska meaning hai:

  • Service SSL/TLS use kar rahi hai.
  • Nmap exact application protocol identify nahi kar paya.

Bandit Level 16 mein correct service 31790 par ssl/unknown ke roop mein identify hoti hai.

openssl s_client

RSA Private Key

RSA Key Kya Hoti Hai?

RSA ek public-key cryptography algorithm hai. SSH key authentication mein private key ka use user ki identity prove karne ke liye hota hai.

Private key output usually in markers ke beech hoti hai:

-----BEGIN RSA PRIVATE KEY-----
...
-----END RSA PRIVATE KEY-----

Key Copy Karne Ke Important Rules

Private key copy karte waqt:

  • BEGIN line include karein.
  • END line include karein.
  • Beech ki har line exactly preserve karein.
  • Extra spaces add na karein.
  • Line breaks preserve karein.
  • Terminal formatting characters copy na karein.
  • Key ke andar random @ ya Unicode characters accidentally add na karein.

Important: Aapke pasted RSA key transcript mein kuch characters corrupted dikh rahe hain, jaise @, spaces aur non-ASCII characters. Website writeup mein key ka full corrupted block paste karne ke bajay explain karein ki key ko service ke actual output se exactly copy karna hai.

Temporary Directory

/tmp Directory

Private key ko /tmp ke andar temporary working directory mein save karna convenient hota hai.

mkdir /tmp/trial
cd /tmp/trial

nano Editor

Key file create karne ke liye:

nano rsa.key

Paste karte waqt complete key format preserve karein:

-----BEGIN RSA PRIVATE KEY-----
KEY_CONTENT
-----END RSA PRIVATE KEY-----

Nano mein save karne ke steps:

Ctrl + O  → Save
Enter     → Filename confirm
Ctrl + X  → Exit

Key File Verify Karna

ls

Expected output:

rsa.key

Private key ki validity test karne ke liye:

ssh-keygen -y -f rsa.key

Agar key valid hai, to public key output generate hoga.

chmod 600

File Permissions

SSH private keys ko secure permissions chahiye hoti hain. Agar key file group ya others ke liye readable ho, SSH warning ya error de sakta hai.

Correct permission command:

chmod 600 rsa.key

600 Ka Meaning

6 → Owner: read + write
0 → Group: no permissions
0 → Others: no permissions

Permission format:

rw-------

Only file owner key ko read aur modify kar sakta hai.

Permissions Check Karna

ls -l rsa.key

Expected format:

-rw------- 1 bandit16 bandit16 ... rsa.key

SSH Login With RSA Key

Private key se bandit17 par localhost login:

ssh -i rsa.key bandit17@localhost -p 2220

Command ke parts:

-i rsa.key → RSA private key use karo
bandit17   → Next user
localhost  → Same machine
-p 2220    → Bandit SSH port

Common Errors

Wrong Port Select Karna

31518 SSL/echo service hai. Ye input ko echo kar sakti hai.

Correct credential service:

31790/tcp open ssl/unknown

Connection Refused

Check karein:

  • Port 31790 correct hai.
  • Host localhost correct hai.
  • OpenSSL command correct hai.
openssl s_client -connect localhost:31790

RSA Key Invalid

Possible reasons:

  • Key copy karte waqt line break remove ho gayi.
  • BEGIN ya END marker missing hai.
  • Key ke andar extra spaces add ho gaye.
  • Terminal ke random characters copy ho gaye.
  • Unicode characters accidentally insert ho gaye.

Key ko actual service output se dobara copy karein.

Permissions Too Open

Error:

WARNING: UNPROTECTED PRIVATE KEY FILE!

Correct command:

chmod 600 rsa.key

Permission denied (publickey)

Check karein:

ls -l rsa.key

Correct login command:

ssh -i rsa.key bandit17@localhost -p 2220

.ssh/known_hosts Warning

Agar ye warning aaye:

Could not create directory '/home/bandit16/.ssh' (Permission denied).

To iska matlab host key save nahi hui. Ye private key invalid hone ka direct proof nahi hai. Agar SSH bandit17 prompt open kar de, to login successful hai.

Password Characters Confuse Hona

Password mein similar characters carefully verify karein:

W vs w
O vs 0
1 vs l

Final password ko actual command output se copy karein:

cat /etc/bandit_pass/bandit17

Security Lessons

Is level se humein ye important lessons milte hain:

  • Port scanning open services identify karne mein help karta hai.
  • Service detection port ke behavior ko samajhne mein useful hai.
  • Echo service aur credential service alag ho sakti hain.
  • SSL-enabled services ko OpenSSL client se test kiya ja sakta hai.
  • RSA private keys ko secret rakhna chahiye.
  • Private key file permissions restrictive honi chahiye.
  • chmod 600 private key ko owner-only read/write permission deta hai.
  • /tmp temporary security workspace ke roop mein useful hai.
  • Exact key formatting SSH authentication ke liye important hai.
  • Nmap sirf authorized systems par use karna chahiye.
