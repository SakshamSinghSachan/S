Git Ignore Concept

.gitignore Kya Hota Hai?

.gitignore ek special file hai jo Git ko batati hai ki kaunse files aur directories ko track nahi karna hai.

Common patterns:

  • *.txt → Saare .txt files ignore honge
  • node_modules/ → node_modules directory ignore hogi
  • .log → Saare .log files ignore honge

Is Level Mein Problem

.gitignore file mein hai:

*.txt

Iska matlab saare .txt files (including key.txt) ignore ho jayenge aur Git unhe track nahi karega.

Solution: .gitignore file ko remove karna hai.

Git Push Workflow

Basic Steps

  1. Create file: key.txt with content May I come in?
  2. Remove .gitignore: rm .gitignore
  3. Add file: git add .
  4. Commit: git commit -m "message"
  5. Push: git push origin master

Common Errors

Wrong Port

Port 2220 use karein, 22 nahi.

git clone ssh://bandit31-git@localhost:2220/home/bandit31-git/repo

Wrong Username

Git username bandit31-git hai, bandit31 nahi.

Wrong Password

Git password bandit31 ka password hai (same as current user).

Wrong File Content

File content exactly same hona chahiye:

echo "May I come in?" > key.txt

Incorrect:

echo "May i come in?" > key.txt  # Lowercase 'i'
echo "May I come in" > key.txt   # Missing '?'

.gitignore Not Removed

Agar .gitignore remove nahi kiya, to key.txt track nahi hoga:

git status

Output will show key.txt as untracked.

Wrong Branch

Task specifies master branch. Default branch par hi push karein.

Push Authentication Failed

Push karte waqt bandit31 ka password enter karein (same as current user).

Password Copy Error

Password:

rmCBvG56y58BXzv98yZGd07ATVL5dW8y

Check karein:

  • Uppercase aur lowercase characters same hain.
  • 0 aur O ko carefully distinguish karein.
  • Password ke start ya end mein extra space nahi hai.

SSH Permission Denied

Next level par login karte waqt check karein:

  • Username bandit32 hai.
  • Port 2220 use ho raha hai.
  • Remote server se mila exact password copy hua hai.

Security Lessons

Is level se humein ye important lessons milte hain:

  • .gitignore files sensitive data leaks prevent kar sakti hain.
  • .gitignore bypass karke sensitive files accidentally commit ho sakti hain.
  • Remote repositories push hooks ke through validation kar sakti hain.
  • Git push workflows mein authentication important hai.
  • File content validation server-side bhi ho sakta hai.
  • Development workflows mein .gitignore carefully configure karna chahiye.
  • Git hooks automated checks aur validations ke liye use ho sakte hain.
