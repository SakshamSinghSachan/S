Cron Kya Hota Hai?

Cron Scheduler

Cron Linux ka time-based job scheduler hai. Ye commands ya scripts ko automatically run karta hai.

Cron jobs ka use commonly in tasks ke liye hota hai:

  • Backups
  • Log rotation
  • System maintenance
  • Monitoring
  • Scheduled reports
  • Temporary file creation
  • Automated scripts

Cron Daemon

Cron jobs ko execute karne wala background service cron daemon kehlata hai.

Daemon continuously background mein run karta hai aur scheduled jobs ke time ko check karta rehta hai.

Cron Job

Cron job ek scheduled command hoti hai.

Example:

* * * * * user command

Iska meaning hota hai ki command har minute run hogi.

Cron Schedule Format

Five Fields

Traditional cron schedule mein five time fields hoti hain:

minute hour day-of-month month day-of-week

Example:

* * * * * command

Fields:

Field Meaning
First * Minute
Second * Hour
Third * Day of month
Fourth * Month
Fifth * Day of week

Five Asterisks Ka Meaning

* * * * *

ka meaning hai:

Har minute
Har hour
Har day
Har month
Har day of week

Isliye job approximately har minute execute hoti hai.

@reboot

Cron files mein @reboot bhi aa sakta hai:

@reboot user command

Iska meaning hai ki system reboot hone par command run karo.

Challenge ke environment ya copied output mein @reboot aur five-star schedule dono dikh sakte hain. Relevant point ye hai ki script automatically execute ho rahi hai.

Cron Job Line

Configuration line ka typical format:

* * * * * bandit22 /usr/bin/cronjob_bandit22.sh &>/dev/null

Is line ke parts:

* * * * *                    → Schedule: every minute
bandit22                    → Job kis user ke privileges mein run hogi
/usr/bin/cronjob_bandit22.sh → Execute hone wali script
&>/dev/null                 → stdout aur stderr suppress

User Field

System cron files mein schedule ke baad user name hota hai:

bandit22

Iska meaning hai ki script bandit22 user ke privileges mein execute hogi.

Script Path

/usr/bin/cronjob_bandit22.sh

Ye actual shell script ka absolute path hai.

&>/dev/null

Bash mein standard output aur standard error dono ko /dev/null par redirect karta hai.

stdout + stderr → /dev/null

/dev/null ek special device hai jo data discard kar deta hai.

Isliye cron script ka output screen par appear nahi hota.

Cron Script Read Karna

Command:

cat /usr/bin/cronjob_bandit22.sh

Script ka corrected format:

#!/bin/bash
chmod 644 /tmp/t706lds9S0RqQh9aMcz6ShpAoZKF7fgv
cat /etc/bandit_pass/bandit22 > /tmp/t706lds9S0RqQh9aMcz6ShpAoZKF7fgv

Important: Aapke pasted command mein chmod 644/tmp/... dikh raha hai. Correct syntax mein 644 aur path ke beech space hota hai:

chmod 644 /tmp/filename

Shebang

#!/bin/bash

Shebang system ko batata hai ki script Bash interpreter ke through execute honi chahiye.

chmod 644

chmod 644 /tmp/filename

Temporary file ki permissions set karta hai.

Permission 644 ka meaning:

6 → Owner: read + write
4 → Group: read
4 → Others: read

Symbolic form:

-rw-r--r--

Iska important result hai ki file everyone ke liye readable ho jati hai.

Output Redirection >

Script ki second line:

cat /etc/bandit_pass/bandit22 > /tmp/filename

> output redirection operator hai.

Meaning:

/etc/bandit_pass/bandit22 ka content read karo
        ↓
/tmp/filename mein write karo

Agar target file already exist karti hai, > usse overwrite kar sakta hai.

/tmp Directory

Temporary Files

/tmp directory temporary files ke liye use hoti hai.

Cron script password ko directly display nahi karti. Iske badle password ko /tmp ke andar ek file mein copy karti hai.

Common Errors

No Such File or Directory

Possible reasons:

  • Temporary filename incorrectly typed hai.
  • 0 aur O confuse hua hai.
  • Script ka exact path read nahi kiya.
  • Cron job ne file abhi create nahi ki.

Script dobara read karein:

cat /usr/bin/cronjob_bandit22.sh

cat Without Filename

Agar aap sirf ye type karte hain:

cat

To cat standard input ka wait karegi. Correct filename provide karein:

cat cronjob_bandit22

Wrong Permission Syntax

Incorrect:

chmod 644/tmp/file

Correct:

chmod 644 /tmp/file

Password File Empty Hai

Cron job ko run hone ke liye thoda time lag sakta hai. Kuch seconds wait karke dobara try karein:

Security Lessons

Is level se humein ye important lessons milte hain:

  • Cron jobs commands ko automatically execute karti hain.
  • /etc/cron.d/ system-level scheduled jobs contain karta hai.
  • Cron file se command aur executing user identify kiya ja sakta hai.
  • Scripts ko read karke unka exact behavior samjha ja sakta hai.
  • Output redirection sensitive data ko temporary file mein store kar sakti hai.
  • chmod 644 file ko everyone ke liye readable bana sakta hai.
  • /tmp files ko secure samajhna dangerous ho sakta hai.
  • Scheduled privileged scripts sensitive information expose kar sakti hain.
  • Exact paths ko guess nahi karna chahiye; source script se verify karna chahiye.
  • Cron misconfiguration security vulnerability create kar sakti hai.
