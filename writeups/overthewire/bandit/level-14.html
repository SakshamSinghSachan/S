OverTheWire Bandit — Level 13 to Level 14

Introduction

Is writeup ka heading Level 13 → Level 14 hai.

Is level mein humein direct password nahi diya jata. Humein ek private SSH key di jaati hai:

sshkey.private

Is private key ka use karke bandit14 user ke account par SSH login karna hai. Login ke baad hum /etc/bandit_pass/bandit14 file read kar sakte hain.

Challenge ka main concept hai:

Password authentication ke bajay SSH private-key authentication

Objective

Is level mein humein:

  • bandit13 user se SSH ke through login karna hai.
  • sshkey.private private key identify karni hai.
  • -i option se private key specify karni hai.
  • localhost ka meaning samajhna hai.
  • bandit14 user ke account par login karna hai.
  • /etc/bandit_pass/bandit14 file read karni hai.
  • Next password copy karna hai.

Private SSH Key

SSH Authentication Methods

SSH login ke do common methods hain:

Password Authentication

ssh username@host -p port

Is method mein server password prompt karta hai.

Private-Key Authentication

ssh -i private_key username@host -p port

Is method mein SSH private key ka use karke identity prove ki jaati hai.

Bandit Level 13 mein private-key authentication use hoti hai.

Private Key Kya Hota Hai?

Private key ek secret cryptographic key hoti hai jo SSH authentication ke liye use hoti hai.

SSH key pair mein do keys hoti hain:

Private key → User ke paas secret rehti hai
Public key  → Server par stored hoti hai

Private key ko kabhi publicly share nahi karna chahiye.

Key-Based Authentication Kaise Kaam Karti Hai?

Simplified process:

Client ke paas private key
          ↓
Server ke paas matching public key
          ↓
SSH challenge-response verification
          ↓
User authenticated

Server private key ko directly receive nahi karta. Client private key se prove karta hai ki uske paas matching secret hai.

-i Option

-i Ka Meaning

SSH command mein -i option identity file specify karta hai.

Command:

ssh -i sshkey.private bandit14@localhost -p 2220

Yahan:

-i sshkey.private → Is private key ko authentication ke liye use karo

Agar -i option nahi lagayenge, to SSH default key locations search karega. Is challenge mein correct private key explicitly specify karni hoti hai.

Identity File Kya Hoti Hai?

Identity file woh file hoti hai jisme SSH private key stored hoti hai.

Is level mein identity file hai:

sshkey.private

localhost Kya Hota Hai?

Localhost Meaning

localhost ek hostname hai jo current machine ko refer karta hai.

Common localhost addresses:

127.0.0.1  → IPv4 localhost
::1        → IPv6 localhost

Jab hum ye command run karte hain:

ssh -i sshkey.private bandit14@localhost -p 2220

To hum remote internet server par nahi, balki current Bandit machine par SSH service se connect kar rahe hote hain.

Bandit Mein Localhost

Pehle hum external Bandit server par login karte hain:

bandit13@bandit.labs.overthewire.org

Uske baad bandit13 machine ke andar se same machine par bandit14 user ke account mein SSH login karte hain:

bandit14@localhost

Simple diagram:

Your Computer
      ↓ SSH
Bandit Server as bandit13
      ↓ SSH to localhost
Same Bandit Server as bandit14

Port 2220

-p Option

SSH mein -p option connection port specify karta hai:

-p 2220

Complete command:

ssh -i sshkey.private bandit14@localhost -p 2220

Yahan:

-p 2220 → Port 2220 par SSH service se connect karo

-p Aur -i Mein Difference

Option Meaning
-i Identity/private key file specify karta hai
-p SSH connection port specify karta hai

Correct command mein dono options use ho rahe hain:

ssh -i sshkey.private bandit14@localhost -p 2220

Host Key Verification

First-Time Connection Warning

Pehli baar localhost:2220 se connect karte waqt SSH warning show kar sakta hai:

The authenticity of host '[localhost]:2220' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?

Ye warning isliye aati hai kyunki SSH client ne is host aur port combination ko pehle known_hosts file mein save nahi kiya.

Learning environment mein type karein:

yes

Host Key Kya Hoti Hai?

Host key server ki identity verify karne ke liye use hoti hai.

SSH future connections par saved host key ko current host key se compare karta hai. Agar key change ho jaye, to SSH security warning display kar sakta hai.

Known Hosts Warning

Aapke output mein ye warning aa sakti hai:

Could not create directory '/home/bandit13/.ssh' (Permission denied).
Failed to add the host to the list of known hosts (/home/bandit13/.ssh/known_hosts).

Iska matlab hai ki SSH host key ko known_hosts file mein save nahi kar paya.

Is warning ke baad bhi connection successful ho sakta hai, agar key authentication correct ho.

User Permissions

bandit13 Ki Limitation

bandit13 user ko ye file directly read karne ki permission nahi ho sakti:

/etc/bandit_pass/bandit14

Har user ko system ki har file access karne ki permission nahi hoti.

bandit14 Ke Through Access

Private key se bandit14 user ke account par login karne ke baad hum command run karte hain:

cat /etc/bandit_pass/bandit14

Ab file access allow hota hai kyunki current user bandit14 hai.

Authentication change hone ke baad permissions change nahi hoti; sirf current user identity change hoti hai.

/etc/bandit_pass Directory

Directory Kya Hai?

/etc/bandit_pass directory mein Bandit levels ke passwords stored hote hain.

Example entries:

bandit13
bandit14
bandit15
bandit16

Har file ka access permissions ke according controlled hota hai.

Directory Mein Jaana

cd /etc/bandit_pass

Files list karne ke liye:

ls

Specific password file read karne ke liye:

cat bandit14

Direct path se bhi read kar sakte hain:

cat /etc/bandit_pass/bandit14

Direct path method recommended hai kyunki isse directory change karne ki zaroorat nahi padti.

Common Errors

Permission denied (publickey)

Possible reasons:

  • Private key ka path wrong hai.
  • -i sshkey.private option missing hai.
  • Username bandit14 galat type hua hai.
  • Aap bandit13 home directory mein nahi ho.

Check karein:

ls -l sshkey.private

Correct command:

ssh -i ./sshkey.private bandit14@localhost -p 2220

Private Key File Not Found

Error:

Identity file sshkey.private not accessible

Current directory check karein:

pwd
ls

Agar key current directory mein nahi hai, to complete path use karein:

ssh -i /home/bandit13/sshkey.private bandit14@localhost -p 2220

Could Not Create Directory .ssh

Error:

Could not create directory '/home/bandit13/.ssh' (Permission denied).

Ye known hosts file save na hone ki warning hai. Iska matlab private key necessarily wrong nahi hai.

Agar connection successful ho jaye aur prompt bandit14@bandit show kare, to aap login kar chuke ho.

Permission denied While Reading Password

Agar bandit13 ke account mein rehkar run karein:

cat /etc/bandit_pass/bandit14

To permission denied aa sakta hai.

Pehle bandit14 ke account mein login karein:

ssh -i sshkey.private bandit14@localhost -p 2220

Phir run karein:

cat /etc/bandit_pass/bandit14

Wrong Port

Correct port 2220 hai:

ssh -i sshkey.private bandit14@localhost -p 2220

Wrong Username

Correct username:

bandit14

Correct command:

ssh -i sshkey.private bandit14@localhost -p 2220

Security Lessons

Is level se humein ye important lessons milte hain:

  • SSH password ke alawa private key se bhi authentication kar sakta hai.
  • Private key secret credential hoti hai.
  • Public key server par aur private key client ke paas hoti hai.
  • -i SSH identity file specify karta hai.
  • localhost current machine ko represent karta hai.
  • 127.0.0.1 IPv4 localhost address hai.
  • User change karne se file permissions change nahi hoti, lekin current access rights change ho sakti hain.
  • /etc/bandit_pass sensitive password files contain karta hai.
  • Host key verification SSH server identity verify karne mein help karti hai.
  • Known hosts warning aur authentication failure alag problems hain.
  • File permissions Linux security ka important part hain.
