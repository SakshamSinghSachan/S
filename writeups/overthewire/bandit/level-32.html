OverTheWire Bandit — Level 32 to Level 33

Introduction

Is writeup ka heading Level 32 → Level 33 hai.

Is level mein humein ek "uppercase shell" se escape karna hai. Ye shell har input ko automatically uppercase mein convert kar deta hai, jisse normal commands (jaise ls, cat, cd) work nahi karti kyunki Linux commands case-sensitive hote hain.

Solution hai: Shell ke positional parameters ka use karna. Positional parameters ($0, $1, $2, etc.) shell variables hote hain jo arguments represent karte hain.

Humein:

  • Shell environment ko understand karna hai.
  • Positional parameters ka concept samajhna hai.
  • $0 variable ka use karke shell escape karna hai.
  • Password file read karna hai.

Positional Parameters

Positional Parameters Kya Hote Hain?

Shell scripts aur command-line mein positional parameters arguments ko represent karte hain:

  • $0 → Script/program ka naam
  • $1 → Pehla argument
  • $2 → Dusra argument
  • $3 → Teesra argument
  • ... aur aise hi aage

Example

Agar aap run karte hain:

./myscript.sh arg1 arg2 arg3

To:

  • $0 = ./myscript.sh
  • $1 = arg1
  • $2 = arg2
  • $3 = arg3

Is Level Mein

Is uppercase shell mein:

  • $0 = sh (shell program ka naam)
  • Aap $0 type karenge, to uppercase ban jayega: $0
  • Lekin $ aur 0 special characters hain, to wo uppercase nahi honge!

Shell Escape Technique

Problem

Normal commands uppercase ban jaate hain:

>> ls
sh: 1: LS: Permission denied

>> cat /etc/bandit_pass/bandit33
sh: 1: CAT: Permission denied

Solution

$0 variable use karein:

>> $0
$

Ye aapko ek normal shell prompt dega jahan aap regular commands chala sakte hain!

Why It Works

  • $0 shell ka current program name hai (sh).
  • Jab aap $0 execute karte hain, to wo ek naya shell start karta hai.
  • Naya shell uppercase conversion nahi karta.
  • Ab aap normal commands use kar sakte hain!

Alternative Methods

Other Positional Parameters

Aap $1, $2, etc. bhi try kar sakte hain, lekin $0 most reliable hai.

Common Errors

Normal Commands Try Karna

Uppercase shell mein normal commands work nahi karenge:

>> ls
sh: 1: LS: Permission denied

Solution: $0 use karein.

Wrong Variable

$0 use karein, $1 ya $HOME nahi.

>> $0  # Correct
>> $1  # May not work
>> $HOME  # Will be converted to uppercase

Case Sensitivity

Linux commands case-sensitive hote hain:

  • ls ≠ LS
  • cat ≠ CAT
  • Cd ≠ cd

Shell Exit

Password copy karne ke baad shell se exit karein:

$ exit

Password Copy Error

Password:

odHo63fHiFqcWWJG9rLiLDtPm45KzUKy

Check karein:

  • Uppercase aur lowercase characters same hain.
  • 0 aur O ko carefully distinguish karein.
  • Password ke start ya end mein extra space nahi hai.

SSH Permission Denied

Next level par login karte waqt check karein:

  • Username bandit33 hai.
  • Port 2220 use ho raha hai.
  • Shell se mila exact password copy hua hai.

Security Lessons

Is level se humein ye important lessons milte hain:

  • Restricted shells (jaise uppercase shell) bypass kiye ja sakte hain.
  • Shell variables aur positional parameters powerful escape vectors hain.
  • Input validation (jaise uppercase conversion) properly implement karna important hai.
  • Shell environments ko carefully configure karna chahiye.
  • Special characters ($, 0) case conversion se bach sakte hain.
  • Defense-in-depth approach use karna chahiye (multiple layers of security).
  • Restricted shells ko test karna important hai before deployment.
