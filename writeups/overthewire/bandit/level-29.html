OverTheWire Bandit — Level 29 to Level 30

Introduction

Is writeup ka heading Level 29 → Level 30 hai.

Is level mein bhi humein ek Git repository clone karni hai, lekin is baar README.md file mein password ki jagah message hai: <no passwords in production!>

Ye hint hai ki password production branch mein nahi, balki development ya testing branches mein accidentally commit ho sakta hai.

Humein:

  • Git repository clone karni hai.
  • Available branches inspect karni hain.
  • Har branch mein README.md check karni hai.
  • Password find karna hai.

Git Branches

Branches Kya Hote Hain?

Git branches parallel development lines hote hain. Different features, fixes, ya experiments ke liye alag branches use kiye jate hain.

Common branches:

  • master / main → Production/stable code
  • dev / develop → Development code
  • feature/* → New features
  • bugfix/* → Bug fixes

Common Errors

Wrong Port

Port 2220 use karein, 2226 nahi (query mein typo hai).

git clone ssh://bandit29-git@localhost:2220/home/bandit29-git/repo

Wrong Username

Git username bandit29-git hai, bandit29 nahi.

Wrong Password

Git password bandit29 ka password hai (same as current user).

Branch Name Typo

Branch name exactly same honi chahiye:

git checkout remotes/origin/dev

Incorrect:

git checkout dev  # Local branch nahi hai
git checkout origin/dev  # Also works, but be consistent

Detached HEAD Confusion

Remote branch checkout karne par detached HEAD state normal hai. Wapas master par jaane ke liye:

git checkout master

Production Message Ignore

<no passwords in production!> message ko hint ki tarah lein. Password production branch mein nahi, development branches mein hoga.

Password Copy Error

Password:

xbhV3HpNGLTIdnjUrdAlPzc2L6y9E0nS

  • Uppercase aur lowercase characters same hain.
  • 0 aur O ko carefully distinguish karein.
  • Password ke start ya end mein extra space nahi hai.

Security Lessons

Is level se humein ye important lessons milte hain:

  • Development branches mein sensitive data accidentally commit ho sakta hai.
  • Production code sanitize hone ke baad bhi dev branches mein data leak ho sakta hai.
  • Git repositories mein secrets management critical hai.
  • Branch-based access control important hai.
  • Code review processes sensitive data leaks prevent kar sakte hain.
  • Pre-commit hooks secrets detection mein help kar sakte hain.
  • Environment-specific configuration files .gitignore mein hone chahiye.
  • Secrets management tools (Vault, AWS Secrets Manager) use karne chahiye.
